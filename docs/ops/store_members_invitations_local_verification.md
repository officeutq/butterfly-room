## 利用者によるローカル確認

DB項目を追加した後は、起動済みの開発サーバーも再起動し、追加項目の認識を更新する。

```bash
docker compose exec -T app bin/rails db:migrate
docker compose restart app
```

開発サーバー：<http://app.localhost:3000/admin/casts>

1. 店舗管理者でログインし、対象店舗を選ぶ。
2. 「所属一覧」でキャストと店舗管理者の表示を確認する。
3. 「キャスト招待一覧」「管理者招待一覧」それぞれで「招待URLを発行」を押す。
4. メモ・共有／コピー・閉じるを確認し、一覧に反映されることを確認する。
5. 別の招待を発行して共有前にキャンセルし、一覧に残らないことを確認する。

この通常の開発画面で発行する招待はローカルDBへ保存される。未共有の確認用招待はモーダルのキャンセルで無効化できる。

## 開発サーバーのDB項目認識の復旧（2026-09-22）

- 利用者のChromeで、管理者招待の発行が失敗し、キャンセルでも同じ発行エラーとなって閉じられない症状を確認した。
- 開発DBには追加4項目とmigration（DB構造の変更）の適用履歴があったが、起動済みサーバーは `ActiveModel::UnknownAttributeError: unknown attribute 'request_key' for StoreAdminInvitation` を返していた。新しく起動したRailsプロセスでは4項目すべてを認識できた。
- `invitation_modal_controller.js#close` は発行結果が不明な場合に同じキーで発行結果を復旧し、取り消してから閉じる仕様のため、発行エラーが続く間は閉じられなかった。自動で再試行し続ける処理ではない。
- `docker compose restart app` 後、開いたままのモーダルをキャンセルし、発行・取消の両リクエストが200で成功、一覧へ戻ることを確認した。新規発行後のキャンセルも確認した。
- 復旧は開発サーバーの再起動で行い、アプリケーションコードの変更は不要だった。確認用招待は取消済みの履歴として残し、共有・送信は行っていない。
- 従来の自動確認は新しい専用テストサーバーを起動していたため、起動済み開発サーバーの古いDB項目情報は検出できていなかった。以後はDB変更後の再起動と通常の開発画面での確認を含める。
