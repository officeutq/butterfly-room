## ローカルでの主な確認手順

1. 複数ブースを操作できる利用者でダッシュボードを開く。ヘッダーのブース名から選択し、ブース情報・編集・履歴の対象が一致することを確認する。
2. 編集画面で値を変更し、ヘッダーから別ブースを選ぶ。破棄確認のキャンセルでは元の入力が残り、続行では新しい対象の編集へ移る。
3. 候補1件では名前のみの表示となることを確認する。店舗A・BとAのブース1件の場合は、店舗Bへ変更後のブース未設定と、ブース情報への移動時のAへの自動設定を確認する。
4. 配信準備AからBへ変更する。空き／準備中BならBの準備へ、他者配信中／閉鎖済みBならB情報へ移る。Aの保存済みタイトルと未開始の準備は残る。
5. 本人の配信中・離席中はブース・店舗の切替導線が出ないこと、配信終了後は選択を維持して切替可能になることを確認する。
6. Aを選択中に公開カードのBを開く。キャスト・店舗管理者・システム管理者ともBの視聴画面へ進み、ヘッダーはAのままとなる。選択中Aのカードでは、キャストは準備／復帰へ、管理者は「視聴／配信」の選択へ進む。
7. 準備中の店舗を非公開にしても準備が残り、古い準備画面からの配信開始が拒否されることを確認する。非公開店舗もヘッダーで選択して情報・編集・履歴を利用できるが、準備への入口では理由が表示される。
8. 店舗内の別ブースも含め、配信中・離席中・開始処理中に店舗を非公開へ変更できないことを確認する。画像や店舗名も同時に変更した場合は、全体が保存されない。終了／取消後は非公開にできる。

追加分の自動確認は`public_booth_card_selection_test`、`Stores::PublicationGuardTest`、`Admin::StoreUpdateTest`、`PublisherConnectionConcurrencyTest`で行う。非公開化が先／トークン発行が先の両順序を別DB接続で検証し、未解放接続の見落としや非公開のままの発行を防ぐ。

2026-09-16の追加確認：Rails全体1,627件・14,233項目、JavaScript182件が成功。RuboCop全699ファイルとBrakemanも指摘なし。専用テストDBを使ったChromiumの1440px／390pxで3役割の選択外カード→視聴・選択維持、管理者の選択中カード→視聴／配信モーダル→視聴、キャストのフッター配信POSTを確認した。この自動確認は実機・実IVSの確認とは区別する。

## 利用者によるローカル確認（2026-09-16）

ユーザーから、使用した役割は**キャスト・システム管理者、端末はPC**と報告された。下表は会話で受けた確認結果であり、エージェントによる再実施や、全項目を各役割で個別に試した証跡ではない。

| 確認事項 | 報告された結果 |
| --- | --- |
| 未開始の準備画面 | 不要な「準備終了」が表示されない |
| 本人の配信中・離席中 | ブース・店舗を切り替えられない。開始直後の古いヘッダーの問題も修正を確認 |
| 配信終了後 | 同じブースが選択されたまま、複数候補があれば切り替えられる |
| 配信準備中のA→B | Bの準備画面へ移り、映像・音声が使える |
| 同じアカウントの別タブ・別端末 | 一方で配信開始後、他方からも変更不可。終了後、他方を再読み込みすると変更可能。端末種別はPCと申告され、スマートフォン確認には数えない |
| 準備画面を開いた後に店舗を非公開化 | 配信開始が拒否され、最初から非公開店舗である旨の案内が表示される |
| 配信中の店舗を非公開化 | 非公開化できない |

追加修正の自動確認：#1326（準備終了表示）、#1327（開始直後・古いヘッダー）、#1328（非公開理由の表示）。#1328時点でJavaScript188件、関連Rails24件・138項目が成功。全体1,627件の実行は上記の先行時点の結果であり、追加修正後に全体を再実行したものではない。
