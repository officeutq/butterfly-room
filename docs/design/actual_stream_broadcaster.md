# 配信開始者の記録・参照と旧配信の移行（#1280）

## 人物と記録の意味

| 人物 | 記録 | 用途 |
| --- | --- | --- |
| 準備作成者 | `stream_sessions.started_by_cast_user_id` | 準備を作成した履歴。配信者の代用にはしない |
| ブース担当者 | `Booth#primary_cast_user` / `booth_casts` | 固定の担当・所属表示と既存の配信権限 |
| 配信開始者 | `stream_sessions.broadcast_started_by_user_id` | 実際の配信、コメント管理、人物表示、個人別実績 |
| 操作した人 | 認証済みの `current_user` / Serviceの`actor` | 管理終了・本人操作の認可。実績の人物は書き換えない |

`broadcast_identity_source` は `ivs_confirmed`（配信時にIVSで確認）、`legacy_creator_backfill`（合意した移行補完）、`evidence`（過去の証拠補正）を区別する。根拠・変更前後は `broadcast_identity_evidence` に保存する。参加用トークンは保存・出力しない。

通常の参照はDBだけを使う。共通判定は `StreamSession#broadcaster?`、表示は `stream_broadcaster_name`。空欄を作成者や担当者へ読み替えない。新方式の未開始は「配信未開始」、旧記録や配信開始記録のある空欄は「配信者不明」。旧記録の開始時刻欠落は、未配信の証明にはならない。

## 状態と開始権

Stage（Amazon IVSの配信ルーム実体）はブース固定で、セッション作成時にARNをコピーする。ここでStageを作り直さない。

| 操作・状態 | 開始権の記録 | 確定済み配信者・開始時刻 | ブース状態 |
| --- | --- | --- | --- |
| 準備作成 | なし | なし | standby |
| 配信者トークン発行 | `stream_publish_attempts`に本人と要求IDを先に保存 | なし | standby |
| IVS参加・配信確認待ち | 同じ開始権を保持 | なし | standby |
| 開始確定 | 参加者ID・属性・接続中・配信済みを照合 | 本人と初回確定時刻を一括保存 | live |
| 離席・復帰 | 現在の確定済み要求IDが必要 | 維持 | live ⇔ away |
| 切断・取消・応答消失 | 予約を直ちに空き扱いしない | 確定済みなら維持 | 確定前はstandby、確定後は元の状態 |
| 再接続 | 旧トークン失効と接続不存在を確認して新しい要求ID | 同じ本人・初回時刻を維持 | live / away |
| 終了・管理終了 | 外部接続を終了。残存トークンの開始権は失効確認まで保持 | 履歴として維持 | offline、現在セッション参照解除 |

`stream_session.status = live` は従来どおり準備を含む未終了の意味。成功した配信かどうかは、作成時刻やこのenumだけで判定しない。新方式で作成した準備には `publisher_protocol = 1` を記録する。旧方式の現在セッションは、そのまま新方式の空き準備として利用しない。

### 競合と認可

- `PublisherControl.with_user_lock` による利用者行のロック → ブース → セッションの順序を共通化する。同じ人の別ブース開始と、同じブースへの別人の開始を直列化する。
- 未解放の開始権には利用者・セッションそれぞれの一意索引を設ける。DBの一意制約も重複発行を拒否する。
- 配信の許可は `Authorization::StreamSessionPolicy`。選択できることだけでは発行しない。店舗管理者・システム管理者の既存権限とキャスト担当の制限を維持する。
- 権限があるYはXの未配信準備を利用できる。Yの開始権確保後はXも割り込めない。一度Yで確定したセッションをXへ引き継ぐ機能は提供しない。
- 新規準備、再利用、トークン、直接URL、確定、状態変更で、閉鎖済み・現在セッション不一致・終了済み・別人・旧方式の不明記録を拒否する。不整合を自動修復して空きへ戻さない。
- 本人が配信権限を持つ別ブースに、未帰属の旧現在セッションがある場合も新規開始を止める。旧作成者を本人と断定せず、その旧セッションを管理手順で解決するまで保守的に扱う。
- 招待承認（#1279）は同じ利用者ロック内で `busy_elsewhere?` を再確認する。選択UI（#1255 / #1272）、準備案内（#1276）、ブース管理（#1290 / #1291）の後続Issueはこの共通制御へ接続する。

### 発行・確認・取消

`PublishService#issue_token` は外部APIより先に開始権をコミットする。発行応答が不明な場合も予約を残す。発行成功時はIVSから返された参加者ID・有効期限を保存してからトークンを返す。ブラウザーが生成するUUIDは要求の識別だけに使い、利用者IDは認証から決める。

トークンには `role`、`user_id`、`stream_session_id`、`publish_attempt_id` を付ける。公開されうる属性なので氏名やメールは含めない。配信者の有効期間は1分。30秒の余裕を加え、期限だけでは開始権を解放せず、IVS上で配信者接続がないことも確認する。期限切れでも接続中なら他タブ・他人が置き換えない。通常の再接続でも、直前のトークン発行から最大約90秒待つ場合がある。

`confirm` は現在のStageセッション内の参加者詳細で、参加者ID、4つの属性、`CONNECTED`、`published` を照合する。`published` はそのIVSセッションで配信したことがある意味なので、開始要求ごとに新規トークン・参加者IDを発行し、古い参加者を流用しない。本人・最初の開始時刻・standby→liveを同じDB処理で確定する。成功応答消失後の再確定で時刻を更新しない。

ブラウザーは参加後に確認を再試行する。失敗時や画面離脱時には、同じSDKのStageインスタンスを退出し、開始権の取消を要求する。退出より遅れて参加処理が完了した場合も再度退出する。取消のサーバー応答を受け取れない場合はDB側の予約が保護を続ける。次の準備・発行操作で期限と外部接続を再確認する。

通常終了には最新の本人の要求IDが必要。古い要求は新しい接続を終了できない。管理終了は現セッションの配信者接続すべてを確認して切断する。IVS照会・切断失敗や別セッションの接続混在では終了処理を止め、台帳や未消化返却を進めない。管理操作の権限は既存の管理導線・所属解除導線で確認する。

## 画面・関連機能への対応

| 実コード・用途 | 参照先 |
| --- | --- |
| 配信中の `stream_meta_display`、結果、ブース別履歴 | そのセッションの配信開始者。名前・画像・プロフィールを一致させる |
| セッション指定の共有文・SNS向け情報 | 指定された過去セッションの配信開始者。現セッションへ差し替えない |
| ブース自体の共有、ブースカードの「所属キャスト名」、編集・待機画面 | 固定の担当者を維持。待機画面のお気に入りも担当者に対するもの |
| コメント非表示・解除、配信者コメント強調 | 配信開始者本人 |
| ドリンク消化の自動コメント | 配信開始者。不明ならユーザー未帰属の消化通知。通常チャットはユーザー必須 |
| 管理者の通報カード | 通報者・投稿者とは別に、その配信の配信開始者 |
| `CastMetricsQuery` | 消化台帳・配信時間を配信開始者IDで集計。nilは「配信者不明（未帰属）」行 |

削除済み利用者の表示には既存の匿名化処理を使い、新しいプロフィール公開権限は加えない。通知後も同じ配信情報部分を再描画する。一覧は配信開始者の関連を事前取得する。

売上の発生条件、セッション・店舗・ブースの紐づけ、消化金額、未消化返却、精算・振込処理は変更しない。未帰属分も店舗総額から落とさない。時間は従来どおり対象期間との重複部分で計算し、開始時刻欠落を推計しない。店舗取り分の表示は従来どおり行ごとに70%を切り捨てるため、行の合計には集計単位による端数差があり得る。精算金額はこの表示から再計算しない。

## 旧配信の補完・証拠補正

実行手順は [旧配信者移行手順](../ops/stream_broadcaster_migration.md) を参照。スキーマ追加時に配信開始者を一括補完しない。

- #1289：固定した計画内の旧セッションのうち、基準時点で終了、開始時刻あり、配信開始者空欄、状態・現在参照整合を満たすものだけ作成者で補完する。準備X・実配信Yだった旧配信でも対象ならXとなる、合意した帰属方針である。
- #1287：IVS参加者の保存済み属性等による調査は別手順。証拠が一意・不明・複数を区別し、欠落を作成者で証明したことにしない。証拠補正は指定した終了済み旧配信と、指定した消化自動コメントだけを対象にする。
- どちらも事前確認、具体的な対象ID・前後値・根拠、再実行、後続補正を保持する。普通のチャットや実操作の監査記録を変更しない。

## APIの確認元と実環境検証

`Ivs::Client` は `GetStage.activeSessionId` → `ListParticipants(sessionId, stageArn)` のページ分割 → `GetParticipant` の詳細取得を行う。`DisconnectParticipant` はStage ARNと参加者IDを渡す（`stage_session_id` は存在しない）。履歴調査は `ListStageSessions` をページ分割して指定セッションを照会する。

確認元：[CreateParticipantToken](https://docs.aws.amazon.com/ivs/latest/RealTimeAPIReference/API_CreateParticipantToken.html)、[ListParticipants](https://docs.aws.amazon.com/ivs/latest/RealTimeAPIReference/API_ListParticipants.html)、[GetParticipant](https://docs.aws.amazon.com/ivs/latest/RealTimeAPIReference/API_GetParticipant.html)、[GetStage](https://docs.aws.amazon.com/ivs/latest/RealTimeAPIReference/API_GetStage.html)、[DisconnectParticipant](https://docs.aws.amazon.com/ivs/latest/RealTimeAPIReference/API_DisconnectParticipant.html)、[StageのSDK操作](https://aws.github.io/amazon-ivs-web-broadcast/docs/v1.14.0/real-time-sdk-guides/stages)。

ローカルではAWS SDKの代替応答とAPI引数検証、DB、HTTP、JavaScriptで確認する。実IVSの反映遅延、切断・トークン再利用の実際の挙動、映像と音声、既存環境のデータ件数・証拠保持期間は移行前の実環境確認事項として残す。
