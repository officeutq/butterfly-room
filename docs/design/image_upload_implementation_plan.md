## 3. PRと運用Issueの境界

- 実装Issueは原則1 Issue = 1 PRとする。
- #1153、#1162〜#1166は1 Issue = 1回の明確な検証・運用段階とし、実行環境、commit、コマンド、件数、結果、未確認事項をIssueへ記録する。
- 運用中にコード修正が必要になった場合は、運用Issueへ直接混在させず修正Issue / PRを追加し、再検証してから次段階へ進む。
- AWS・S3変更はIssueに明記した範囲だけを対象にし、無関係なTerraform差分を適用しない。

## 4. リリースgate

次のすべてを満たすまで本番のFilePond経路を撤去しない。

- HEIC decoderの配布条件確認
- User / Store / Booth通常フォームのステージング実機確認
- ステージングdry-run・少数件・全件移行の完了
- 本番dry-run結果のユーザー承認
- 本番移行・事後照合と監視期間の完了
- 未移行・失敗対象が0件、または個別Issueへ分離済み

確定した技術仕様は [Cropper.js画像アップロード確定設計](image_upload_cropper_architecture.md) を参照する。
