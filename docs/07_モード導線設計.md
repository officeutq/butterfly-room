## 0. 目的

2026-09-16の公開カード導線追加は[選択の共通契約7.1節](design/current_selection.md)を優先する。選択外は役割によらず視聴へ進み、選択中の管理者は「視聴／配信」を選ぶ。非公開店舗の配信準備・開始は禁止し、管理の入口は維持する。以下のPhase1記述は変更前の経緯を含む。

[Epic #207] モード導線統一を起点とし、選択改修後の主要な導線と責務を記録する。

* root = ブース・店舗・配信者の3タブ一覧（ログイン済みの初期タブはブース、未ログインの初期タブは店舗）
* ブースクリック導線の一本化（enter導線）
* 選択中の担当ブースではcastは配信準備／復帰へ進む。選択外は視聴へ進み選択を維持
* 選択中の操作可能なブースではstore_admin / system_adminはモーダルで視聴／配信を選択。選択外は視聴
* current_booth / current_store の整合性ルール確定
* ヘッダー / メイン / フッター のレイアウト統一（デザインは後続Issue）
* ポイント表示と購入導線の配置確定

**重要制約**

* URL直書き禁止。遷移は path helper で統一する。
* BAN / archived 除外など既存フィルタを壊さない。

## 2. レイアウト設計（確定）

※ デザインは後続Issueで行う。ここでは構造のみ「ヘッダー / メイン / フッター」を統一する。

### 2-1. ヘッダー（共通）

表示項目：

* ページタイトル（`content_for(:title)` を優先）
* ポイント残高表示（wallet.available_points）

以下、アカウントメニュー
* ユーザー表示（表示名 or email）
* role
* current_store / current_booth の参照表示は role により分岐する
  - cast / store_admin / system_admin：表示する（未選択は未選択表示）
  - customer：表示しない（未選択表示もしない）

アカウントメニュー（右側の名前・アイコンから開くドロップダウン）：

* customer / cast / store_adminには退会導線を表示し、共通の退会確認モーダルを開く
* system_adminには退会導線を表示しない
* ユーザー向けBuild番号表示は廃止し、その位置を退会導線へ置き換える
* ログアウト導線は維持する

未ログイン時はポイントを `0pt`、roleを `GUEST`、丸アイコンを「未」、表示名を「未ログイン」とする。メールアドレス、キャレット、ドロップダウンは表示せず、ポイント領域とユーザー領域だけをログイン要求モーダルの起動リンクとする。

#### Current（store / booth）の切替

候補0件では候補なしを案内し、1件では自動設定する。本人が配信中・離席中なら本人のブース・店舗に固定する。いずれも切替リンク・選択モーダルは出さない。複数候補で本人が未配信の場合は、有効な選択を維持し、ヘッダーから共通モーダルを開ける。

- cast：ブースは `select_modal_cast_booths_path(source: "header", return_to: request.fullpath)`。店舗は名前だけ表示。
- store_admin / system_admin：ブースは同じモーダル、店舗は `select_modal_admin_stores_path(return_to: request.fullpath)`。
- customer：ブース・店舗の管理用選択は表示しない。

未選択で対象が必要な操作へ進む場合も共通モーダルを使う。準備開始成功時はその場でヘッダーを固定する。別タブなどの古いリンクから要求された場合は最新DBで拒否し、移動せず固定の案内を表示する。終了後は同じ選択を維持し、複数候補なら再び変更できる。

### 2-2. フッター（共通トップレベル導線）

導線（左→右）：

* ホーム：`root_path`
* お気に入り：`favorites_booths_path`（customer前提。未ログインはログイン要求モーダルを表示）
* **中央：store_adminはキャスト招待、cast / system_adminは配信**
* お知らせ：`notifications_path`
* ダッシュボード（role別）

ポイント購入はヘッダーの残高、ログアウトはヘッダーのアカウントメニューから行う。

未ログイン時は中央の配信を表示せず、ホーム、お気に入り、お知らせ、ダッシュボードの4項目とする。ホーム以外の3項目は、通常画面、booth視聴画面、公開プロフィールのいずれでも認証必須URLへ直接遷移せず、ログイン要求モーダルを表示する。

#### 中央ボタン表示条件

* `current_user.present? && current_user.at_least?(:cast)` の場合のみ表示
* store_adminの表示名は「キャスト招待」、cast / system_adminは「配信」とする。

#### 配信ボタン遷移先

- cast：選択済みなら `enter_as_cast_booth_path(booth)` へのPOSTで準備／復帰へ。未選択なら `select_modal_cast_booths_path(return_to_key: "booth_live")` で共通判定に進む。
- store_admin：`new_admin_cast_invitation_path` をモーダルで開く。未選択なら店舗選択を挟む。本人が配信する入口は選択中の公開ブースカードの「配信」。
- system_admin：`select_modal_cast_booths_path(return_to_key: "booth_live")`。既に有効な選択があればその準備へ進み、別対象の候補を出さない。変更はヘッダーで行う。

候補なしは案内し、唯一候補・本人配信中はモーダルを出さず固定対象を使う。準備可否は配信制御で別途確認し、閉鎖済み・他者配信中・非公開店舗では準備・開始しない。

#### ポイント購入（既存導線との関係）

* 現行 routes は `wallet_purchases_path` が **POSTのみ**。
* booth_idのない購入では、`CheckoutController#return`は`root_path`へ戻す。現在の共通フッターには購入項目を置かず、ヘッダーから購入フォームを開く。

  * `CheckoutController#return` は `@booth_id` が無い場合 `root_path` に戻る実装で整合している。
* ブース視聴ページ内の購入導線（booth_id付き）は現行維持。

  * booth内購入はブースに戻れる（booth_id付き）

#### ダッシュボード（role別）

ログイン済みの全役割で `dashboard_path_for(current_user)` から `dashboard_path` へ進む。ダッシュボード本文のカードを役割で分ける。未ログインはログイン要求モーダルを表示する。

## 3. root（3タブ一覧）導線設計

### 方針

* ログイン済みのブースカード主リンクは `enter_booth_path`、未ログインは公開閲覧用の `booth_path` とする

* 店舗一覧は現状どおり `store_path(store)`（store側enterは現状対象外）

* 未ログインでも3タブと検索を利用できる
* 未ログイン時、店舗カードと公開店舗詳細は閲覧できる
* 未ログイン時、ブースカード本体・公開対象の配信者名・配信者カードは各詳細へ直接遷移する。未ログインのプロフィール詳細は有効なcastのみ公開する。ログイン済みの詳細は `User.profiles_visible_to` を使用し、トップの掲載条件とは区別する
* 未ログイン時、コメント投稿・通報、ドリンク、お気に入り等の保護操作はログイン要求モーダルを表示する
* 未ログインの配信視聴は購読専用とし、コメントを読み取り専用でリアルタイム表示する。在室ping・視聴者数取得は行わず、視聴者数へ含めない
* 公開店舗詳細では公開店舗に属するactiveブースだけを表示する

### 3.1 管理用の店舗情報（#1251）

`/admin/stores/:id` に店舗画像・基本情報・公開状態、ドリンクメニュー（有効／無効）、振込先口座（未設定／現在の設定・番号は伏字）をまとめる。管理者所属のある店舗管理者とシステム管理者のみが利用でき、公開・非公開を問わない。公開店舗詳細へ管理情報は追加しない。

URL対象を認可した後、共通選択の一致を確認する。選択中BからAのURLへ直接入っても、Aへ選択を変えたりAのURLでBを表示したりしない。未選択時は既存の0／1／複数・本人配信固定のルールで判定し、必要なら既存の店舗選択へ案内する。閲覧によって店舗設定・配信状態・チュートリアル進捗は更新しない。

#1251では表示・認可のみを実装。編集ボタン、保存後の戻り先、ヘッダー切替で新店舗の情報へ追従する処理は#1252で、ダッシュボードカードと初回案内は#1253で接続する。公開詳細の編集リンクも#1252までは現行のままとする。

### 3.2 公開店舗詳細からの編集（#1233 / #1234）

以下は現行の記録。#1252で管理用店舗情報からの編集・戻り先を用意した時点で、公開店舗詳細の編集リンクと`return_to=store_detail`専用復帰を廃止する。公開ブースには編集リンクを追加せず、公開詳細から編集できるのは本人プロフィールのみとする。

* 店舗名付近に鉛筆アイコンと「店舗情報を編集」を表示する。店舗管理者は閲覧中のStoreにadmin所属がある場合、運営管理者は全公開Storeで表示する。未ログイン、customer、cast、管理権限のない店舗には表示しない。
* 入口は `edit_admin_store_path(store, return_to: "store_detail")`。既存の通常編集と認可を使い、選択中の店舗・ブースを切り替えない。複数店舗管理時も閲覧中の店舗を対象にする。
* 編集フォームは固定値 `return_to=store_detail` だけを保持・送信する。任意のURLや別店舗IDを戻り先として受け付けない。未指定・不明な値は従来どおりダッシュボードへ戻す。
* 詳細経由の「戻る」とHTML/JSON保存成功後は、対象Storeが公開中なら `store_path(store)`、非公開なら `dashboard_path`。非公開の公開詳細は引き続き404とする。
* 未保存変更の破棄確認、保存確認、JSON保存失敗時の入力保持を維持する。再試行でも固定の戻り先を保持し、HTML保存失敗時の編集画面へのリダイレクトにも引き継ぐ。
* ダッシュボード・店舗切替・代行登録など従来の編集入口の戻り先は変更しない。初回設定・公開完了・計測とは分離する。

### 未ログイン用ログイン要求モーダル

* タイトルは「ログインが必要です」とする
* ログインまたは視聴者アカウント新規作成が必要であることを本文で説明する
* 「キャンセル」はモーダルを閉じ、「ログイン・新規作成へ」は `welcome_path` へ遷移する
* 既存の `modal` Turbo FrameとBootstrap Modalを再利用する
* モーダルURLへの通常GETは `welcome_path` へフォールバックする

## 4. enter導線の仕様（最重要）

### 4-0. 追加するルート（helper名で統一）

* `enter_booth_path(booth)`（GET）
* `enter_as_cast_booth_path(booth)`（POST）

（routes例：`resources :booths do member { get :enter; post :enter_as_cast } end`）

### 4-1. customer

* `booth_path(booth)` へリダイレクト（視聴）
* BAN防衛：

  * Home/Favoritesは「可能な範囲で予防」
  * 最終防衛は `BoothsController#show` の `StoreBanGuard` が担保
  * enter では最小差分として “showに委ねる” でもOK（ただしUX上は enter側で弾いてもよい。実装Issueで選択）

未ログインの場合はcustomer分岐へ入れず、`welcome_path` へリダイレクトする。

### 4-2. cast

有効な選択と異なる公開カードは`booth_path(booth)`（視聴）へ進み、選択を維持する。選択中かつ`BoothCast`で本人が担当するブースなら、`Booths::EnterAsCastService`で準備・復帰を判定し、成功後に`live_cast_booth_path(booth)`へ進む。担当外は視聴へ進む。

未選択の場合は共通の必要操作のルールに従う。URLの対象を無条件に選択しない。カードの先読みでは準備を作らない。

### 4-3. store_admin / system_admin

有効な選択と異なる公開カードは視聴へ進み、選択を維持する。選択中の操作可能なブースでは「視聴／配信」を選ぶモーダルを表示する。店舗管理者の管理対象外は視聴へ進む。

- 視聴：`booth_path(booth)`（GET）。
- 配信：`enter_as_cast_booth_path(booth)`（POST）。対象の権限と現在選択を改めて確認する。
- 未選択で配信を要求した場合も必要操作の共通選択を挟む。古いモーダルから選択外の対象へ配信POSTしても、選択を上書きしない。

## 5. POST enter_as_cast（配信として入る）

### 実配信者判定（#1280で実装・有効化済み）

「本人が配信中・離席中」の判定はDBに保存した実配信者と現在セッション・ブース状態の整合で行う。準備作成者、担当者、管理権限があるだけでは本人配信中と扱わない。旧準備も同じIDで再利用し、他人の実配信は開始・再接続で引き継がない。

終了・返却済みでもIVS切断待ちがある場合、同じ人物・ブースの次の配信を切断確認まで保留する。情報閲覧・履歴閲覧と配信可否を分け、切断待ちを理由に全ブースの閲覧を止めない。開始要求や切断待ちは「本人が配信中」とは別の状態として表示する。詳細は [実配信者設計](design/actual_publisher.md)。

この変更でブース・店舗選択の全入口を作り直さない。選択方式全体の整理は #1255 の担当とし、#1280はその前提となる人物の保存・共通参照を整備する。

### 目的

store_admin/system_admin が “配信” を選んだ場合、cast側へ安全に入るための共通導線。

### 認可

* system_admin：OK
* store_admin：自店ブースのみOK（`admin_of_store?`）
* cast：BoothCastありのみOK

### 認可OKの場合の動作

認可後に共通選択とURL対象を照合する。対象不一致では選択を上書きせず案内する。`Booths::EnterAsCastService`を呼び、成功後に対象の準備・配信画面へ進む。準備画面自体や準備画面からの切替では`Booths::PrepareSelectedBoothService`が既存の配信制御へ委譲する。候補GET・情報表示だけで準備しない。

## 6. current_booth / current_store の整合

保存キーは `session[:current_booth_id]`・`session[:current_store_id]`。共通判定の成功結果を `CurrentSelection` で一組として保存し、同じ結果をヘッダーへ渡す。ヘルパー独自の補完・URL対象への上書きはしない。

- 有効な選択は維持し、無効なIDのみ除去する。本人配信の固定を優先し、不整合を空きと見なさない。
- 同じ店舗の再選択ではブースを解除しない。店舗を変更した場合はブースを解除し、全候補で唯一のブースが変更先店舗にあれば自動設定する。それ以外はブース未設定を維持する。
- A・B店とAのブース1件なら、A→BはB＋未設定、B→AはA＋唯一のブース。Bの通常表示では未設定を維持し、ブースが必要な操作へ進む時だけA＋唯一のブースに自動設定する（D01）。
- キャスト招待の承認成功時だけ新規ブースと店舗に切り替え、名前付きで通知し初回編集へ進む。表示・失敗・承認済み画面の再表示では切り替えない（D02）。本人配信中・離席中の承認は拒否する。

### 6.1 情報・編集・履歴と表示追従

- キャストの旧「ブース一覧」カードと一覧は廃止。ヘッダーの共通モーダルで変更する。管理側の旧一覧・カードの撤去は#1293で対応する。
- ブース情報・編集・履歴、店舗依存の編集などでヘッダーから変更すると、新しい選択に対応する画面へ移る。公開詳細・個別の配信結果は対象を維持する。[画面別の戻り先](design/current_selection.md)を参照。
- 情報・編集・履歴URLは対象を認可し、現在の選択と照合する。通常のURL閲覧・保存だけで選択を変えない。別タブの古い保存要求は409で拒否し、別対象へ読み替えない。
- 未保存変更があれば選択POST前に破棄確認を出す。キャンセル・選択失敗では元の入力・選択・画面を保持する。本人配信中の切替確認は廃止し、切替そのものを拒否する。
- 準備A→BはBの準備へ進む。他者配信中・閉鎖済み・非公開店舗はBの情報へ案内する。確認不能・取消失敗・準備失敗は切替成功にせずAを保持する。元の未開始準備・保存済みタイトルは終了・削除しない。
- 通常編集の保存・戻る、履歴の戻るはブース情報へ進む。招待直後の編集は保存後ホームへ戻る。
- 管理者は閉鎖済みを選択できる。現時点の情報画面は編集・履歴ボタンが非表示で共有ボタンが残るため、採用仕様の「履歴のみ」に揃える表示変更は#1292に残す。キャストは閉鎖済みを選択できないが、権限のある閉鎖済み履歴の直接閲覧は選択を変えず許可する。

## 7. モーダル設計（共通基盤）

layoutに常設したTurbo FrameとBootstrap Modalを共通基盤として利用する。

方針：

* layoutに共通modal枠を1つ配置
* `<turbo-frame id="modal">` を常設（空でOK）
* `enter` が store_admin/system_admin 向けに “モーダル本文” を返す（HTML partial）
* 遷移ボタンは `_top` で画面遷移（安全優先）

  * 視聴：`booth_path(booth)`（GET）
  * 配信：`button_to enter_as_cast_booth_path(booth)`（POST）を `_top` で実行

### 7.1 プロフィールのアカウント設定モーダルと確認・編集導線（#1244・#1246）

* 視聴者・キャスト・店舗管理者・システム管理者のダッシュボードでは、「プロフィール情報」カードから `user_path(current_user)`（本人のプロフィール詳細）を開く。説明は「プロフィールの確認・編集を行います」とする。
* 電話番号認証カードは設けず、「プロフィール情報」カードに「電話番号認証済み」（緑）／「電話番号未認証」（黄）を表示する。
* プロフィール編集の「アカウント」にメールアドレス・電話番号・認証状態と各操作ボタンをまとめ、「メールアドレス・電話番号は公開プロフィールに表示されません。」と案内する。
* メールアドレス変更と電話番号認証は、それぞれ共通モーダルで完結する。成功後も同じプロフィール編集画面を維持し、未保存の表示名・自己紹介・画像と保存ボタン状態を保持する。
* アカウント変更は各モーダルで独立して確定する。プロフィールの「保存」は不要で、プロフィールの未保存変更を破棄しても確定済みアカウント変更は取り消されない。
* アカウント欄には保存タイミングの追加説明を置かず、変更した項目の直下に「✓ メールアドレスの変更を保存しました」／「✓ 電話番号を認証して保存しました」を表示する。
* プロフィールの「保存」は編集完了の操作として変更の有無にかかわらず押せる。送信中だけ無効化し、通常保存後は本人のプロフィール詳細へ進む。未保存変更の判定は「戻る」等の破棄確認のために維持する。
* 本人のプロフィール詳細では、名前・役割の下に店舗詳細と同じ小型の枠線ボタン・鉛筆アイコンで「プロフィールを編集」を表示する。他人の詳細や未ログイン時には表示しない。
* 通常保存はHTML・画像更新時のJSON応答とも `user_path(current_user)` を返す。キャスト招待後のプロフィール→ブース編集→ホームという専用導線と、対象ブースが見つからない場合のホームへの退避は維持する。
* 電話番号認証は入力→SMS送信→コード入力→登録。途中で閉じた場合は再表示時にコード入力へ戻り、番号の入力し直しも選べる。登録前には既存番号を変更しない。

### 7.2 退会確認モーダル

* プロフィール編集画面下部と右上アカウントメニューの2箇所から、`account_withdrawal_path`を`modal` frameへ読み込む
* モーダルには、履歴・ポイント・所属が新しいアカウントへ引き継がれないことと、ロール別クリーンアップ内容を表示する
* 現在のパスワードと確認チェックを必須とする
* モーダル自体を最終確認とし、ブラウザ標準confirmは重ねない
* 成功時はログアウトし、モーダルframeのリダイレクトマーカーからログイン画面へ遷移する
* 失敗時はモーダル内にエラーを表示し、ユーザーを有効状態のまま維持する

## 8. テスト観点（必須）

* enter分岐の網羅

  * customer → booth_path
  * castの選択中・担当ブース → 準備／本人の配信へ復帰
  * cast他人 → booth_path
  * store_adminの選択中・自店 → 視聴／配信モーダル
  * store_admin 他店 → booth_path
  * system_adminの選択中 → 視聴／配信モーダル
  * 全3役割の選択外 → 視聴、選択維持
* enter_as_cast

  * system_admin OK
  * store_admin 自店OK / 他店NG
  * cast BoothCastありOK / なしNG
  * 認可後に選択対象も照合。古い対象のPOSTは選択を上書きせず拒否
* Current整合

  * boothがある時に store不一致なら補正される
  * 別店舗への変更と同じ店舗の再選択を分け、D01の未設定維持・必要時の自動設定を確認
  * 本人配信中・離席中は固定し、開始直後と別タブの古いヘッダーでも切替不可。終了後は同じ選択を維持
* フッター配信ボタン

  * `at_least?(:cast)` で表示/非表示
* フッター購入導線

  * booth_id無し→ returnはrootへ
  * booth内購入（booth_idあり）→ returnはboothへ
* 未ログイン公開導線

  * rootの初期タブは店舗
  * 公開店舗詳細は成功、非公開店舗詳細は404
  * 画面上のブース・公開キャストは各詳細へ遷移する。コメント投稿者名は全員リンクなし。コメント投稿・通報・ドリンク・お気に入り操作はログイン要求モーダルを開く
  * 公開ブース詳細と有効なcastプロフィールのURL直入力は成功し、他のプロフィールは404
  * 未ログインの映像視聴は購読専用、コメントは読み取り専用リアルタイム、在室・視聴者数は対象外
  * welcome経由のログイン後はroot、新規登録後は通常の初期画面へ

### プロフィール導線（#1213）

* 閲覧可否は `11_画面アクセス権限マトリクス.md` の対象別表を参照する。トップはキャストのみ、お気に入りユーザーは登録済みかつ現在閲覧可能な対象のみ表示する。
* コメント投稿者名は未ログインでは全員リンクなしとする。ログイン済みは閲覧可能な他人と有効な本人だけリンクを表示する。コメント本文・名前・アイコンの表示は維持する。
* 未ログインでも有効なキャストのプロフィール詳細URLとトップからの導線は利用できる。コメントのリンク非表示だけを閲覧認可として扱わない。

### キャスト招待・一覧・チュートリアル（#1237〜#1239）

ダッシュボードの旧「キャスト招待」カードを廃止し、「キャスト一覧」から所属キャスト・キャスト招待一覧の2タブへ進む。初期タブは所属キャスト、`admin_casts_path(tab: "invitations")` は招待一覧。旧招待一覧URLは新タブへ転送し、店舗未選択なら選択後に新タブへ戻る。招待一覧は閲覧専用でURL・操作ボタン・取消済み招待を表示しない。

招待操作は共通フッターの「キャスト招待」からモーダルへ集約する。視聴専用の4項目フッターや他ロールの配信導線は変更しない。共有・コピー後もモーダルを残し「閉じる」を表示する。メモは共有・コピー押下時に保存し、その後に編集した場合は閉じる際に保存する。

共有する本文は店舗名・管理者表示名・参加案内に続けて招待URLを含める。本文のみを受け取るメールなどの共有先でもURLが欠落しないよう、別のURL欄には重複して渡さない。コピーの場合はURLのみとする。

チュートリアルは初回店舗設定・登録完了のサンクスページでは表示せず、その後の店舗ページから開始する。「フッターのキャスト招待 → モーダルで共有・コピー → 閉じる → ダッシュボード → ドリンク設定」の順に案内する。モーダル表示中は背後への吹き出しを止め、モーダル内の共有・コピーと閉じるボタンを案内する。閉じた後に次の案内を表示する。旧招待画面へのアクセスで進捗を進めない。
