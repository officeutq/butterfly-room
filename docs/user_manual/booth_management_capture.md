## 再現方法

ローカルのDocker Composeで`app`・`db`を起動し、npm依存とPlaywrightのChromiumを用意して実行する。

```powershell
node tests/manual_capture/booth_management.cjs
```

- ポート3015を使う。既存の開発サーバー3000や選択撮影サーバー3102は停止・再利用しない。
- 毎回`butterfly_room_booth1294_<ランダム8桁>`という空のテストDBを作る。同名DBが存在すれば停止し、既存DBを初期化しない。
- `booth_management_fixture.rb`はtest環境・DB名・初期データなしを検証する。AWS SDKの応答を差し替え、無効な撮影用認証値を渡す。実Stageへの通信は行わない。
- 既定entrypoint（起動処理）による共有PIDファイルの削除を避け、`--entrypoint bundle`で起動する。testレイアウトでは省略される既存Bootstrap IconsのCSSだけを撮影用ブラウザーで追加読込し、アプリのテンプレートは変更しない。
- 成否にかかわらず、今回起動した一時コンテナだけを停止する。DBと`tmp/booth1294-<識別子>/`の画像・ログは調査用に残し、自動削除しない。
- ログイン用のランダムパスワードはプロセス間だけで受け渡し、結果JSON・マニュアルに出力しない。

## 撮影内容と判定

3役割（キャスト・店舗管理者・システム管理者）×1440px／390pxの6組合せで撮影する。架空の配信中データを管理者が強制終了し、同じブースを閉鎖する。実カメラ／マイク・実IVS・配信者側ブラウザーは使わない。

| 画面・操作 | 撮影／判定 |
| --- | --- |
| ヘッダー共通選択・ダッシュボード | 旧一覧カードなし。管理者だけ新規作成カード。選択行に個別管理ボタンなし |
| 新規作成 | 管理者の所属店舗表示・戻る先を確認。今回は保存しない。保存は#1293のブラウザー試験と既存Rails試験を参照 |
| 未閉鎖情報 | キャストに管理操作なし。管理者の配信中は強制終了のみ |
| 強制終了→閉鎖→履歴→情報 | 確認文の対象一致・取消／確定、同じ情報への復帰、閉鎖済みの操作は履歴のみ |
| 閉鎖済みretrying／failed／履歴0件 | 管理者は状態表示、キャストは管理状態なし。どちらも履歴と戻るを利用可能 |
| 結果未確認 | テストキューの再試行を実行せずretryingを維持し、有限なGET取得後に再読込案内へ変わることを確認 |
| 最終DB比較 | 管理対象4件の終了・閉鎖、AWS代替切断4回を確認。過去履歴・事前作成した未確認接続は全属性不変。ブース・配信・接続の追加なし |

JavaScript例外と横方向の画面はみ出しがないことも確認する。状態取得失敗・通知更新・返却・競合・古い世代は[横断検証記録](../design/booth_management_validation.md)に対応する自動テストを参照する。
